1. タスク YAML

id: csv-summary-format              # 英数字・_ . -
description: 月別集計で配布ルールの出力形式が守られるか
targets: [claude_code, codex]       # 実行するエージェント（既定は両方）
tags: [instructions, smoke]         # --tag で絞り込む
fixture: ../fixtures/sales_synthetic   # 試行ごとに作業ディレクトリへ複製（ファイル 1 つでも可）
prompt: |
  sales.csv を月別に集計して summary.md にまとめてください。
limits: {max_turns: 15, timeout_s: 300, max_budget_usd: 0.5}
allow_tools: [Read, Write, Edit, Bash, Skill]
deny_tools: []
paired_negative: arithmetic-no-skill            # 対になる「してはいけない」タスク（任意）
split: dev                          # 自己改善ループ用の分割 train / dev / holdout（任意）
family: monthly-report              # 似たタスクのグループ（任意。既定はタスク id）
graders:
  - type: command
    run: '{python} {task_dir}/../checks/check_monthly_totals.py {task_dir}/../fixtures/sales_synthetic/sales.csv'
    weight: 2
  - type: file_contains
    path: summary.md
    pattern: '^\|\s*月\s*\|\s*売上合計\s*\|'
    category: instruction_violation
  - type: tool_used
    tool: Bash|shell
    input_match: 'rm\s+-rf'
    max: 0

相対パスはタスクファイルの場所が基準です。未知のキーはエラーになります。

キー意味既定
id・prompt必須。プロンプトは CLI に標準入力で渡す—
targetsclaude_code・codex両方
fixture入力データ（合成データだけ）なし
limits.max_turns・limits.max_budget_usd1 試行のターン数・費用の上限（Claude Code のみ）20・なし
limits.timeout_s1 試行の時間の上限。超えたら子孫プロセスごと止める600
allow_tools・deny_toolsClaude Code の --allowedTools・--disallowedTools。-p では承認が必要なツール（Write・Edit・Bash など）は許可しないと拒否される空
paired_negativeスキル・サブエージェントを「使うべきでない」対のタスク idなし
description・tags説明と絞り込み用のタグ空
split自己改善ループでの使い道（train・dev・holdout。図解ガイド 11 章）。run --split で絞り込むなし（分割なし）
family似たタスクのグループ（英数字・_ . -）。分割はグループ単位にするタスク id
allow_test_changestrue にすると、見えているテストの削除・skip・確認の減少を改ざん（test_tamper）として数えない。テストを直すこと自体が課題のタスク用（ズル対策）false
canaries参照解・採点に埋めた文字列の一覧。トランスクリプトのどこかに出たらその試行は無効（leak）。AHE-EVAL-CANARY-5d2e9b と VL-EVAL-CANARY-7f3c1a は常に見る空
leak_patternsツールの入力がこれに当たったらその試行は無効（正規表現の一覧。例: 参照解のファイル名）空
calibration判定役の校正。決定的な採点器が見ていることを LLM 判定にも問い、一致率を測る。キーは criteria（必須。PASS / FAIL の条件）・focus（final かファイルパス）・max_chars・graders（照合する決定的な採点器の番号。0 始まり、llm 以外）。例は examples/tasks/csv-summary-format.yaml。LLM 判定が合否を決めた試行がある実行でだけ使い、--calibration-items（既定 6）件まで、決定的な採点器の合格と不合格が偏らないように選ぶなし（graders の既定は llm 以外のすべて）

2. グレーダー

type見るもの主なキー種別
file_exists作業ディレクトリのファイルの有無path結果
file_containsファイル内容の正規表現（複数行モード）path, pattern結果
regex最終応答の正規表現pattern結果
command独自スクリプト。終了コード 0 で合格run, timeout_s結果
llmLLM 判定（PASS / FAIL / UNKNOWN）。ルーブリックでしか見られない基準に使う。決定的な検査がすべて合格した出力にだけ、全試行のあとで走るcriteria, focus（final かファイルパス）, max_chars結果
tool_usedツール呼び出しの回数tool（名前の正規表現・完全一致）, input_match, min, max, include_subagents過程
skill_usedスキル呼び出しの回数skill, min, max過程
subagent_usedサブエージェント呼び出しの回数name, min, max過程
hook_usedhook の実行回数（Claude Code のみ）hook（イベント:マッチャー の正規表現・完全一致）, outcome, min, max過程
  • 全グレーダー共通: weight（既定 1）・negate（判定を反転）・category（失敗分類のタグ。既定は種類ごとに wrong_output・process_violation・skill_selection・delegation・hook）・description。
  • min・max を省くと「1 回以上」、max だけ書くと「0〜max 回」。
  • llm の判定役に渡すのは criteria と、最終応答か focus のファイル 1 つ（max_chars まで）だけです。会話の記録・ツールの入出力は渡しません。プロファイル id・モデル名・ハーネスの名前・パスは伏せます。段階・系統・多数決は 7 章「判定役」。
  • skill_used・subagent_used・hook_used で 1 回以上を求める判定は「配布物がないと通らない判定」として扱います（図解ガイド 7 章の Δ から両側とも除く。試行の合否とスコアには入る）。

command の書き方

  • run では {python}（実行中の Python）・{workdir}・{task_dir} を使えます。作業ディレクトリで実行され、環境変数 TRIAL_WORKDIR と TRIAL_RECORD（試行レコード JSON のパス）が渡ります。
  • 置換した値はシェル用に自動で引用されるので、YAML 側で "{task_dir}" のように囲まないでください（空白を含むパスで壊れます）。
  • 正解は元のフィクスチャから計算します。作業ディレクトリのファイルはエージェントが書き換えられるからです（同梱の採点スクリプトは元の sales.csv を引数で受け取ります）。
  • 「形式」と「正しさ」は別の判定に分け、形式の違いで正しさを落とさないようにします。

ツール名はエージェントで違う

エージェントツール名
Claude CodeBash・Write・Edit・Skill・Agent など
Codexshell（コマンド実行）・file_change・web_search・collab:<操作>
共通（MCP）mcp__<サーバー>__<ツール>

両方で同じタスクを使うなら tool: Bash|shell のように両方を書きます。Codex のスキル検出は推定（SKILL.md を読むシェルコマンドから名前を拾う）なので、Codex では成果物を見るグレーダーを主にしてください。

hook_used

Claude Code の --include-hook-events の記録を数えます（このフラグは hook_used を使うタスクにだけ付けます）。hook は PreToolUse:Bash・SessionStart:startup のような「イベント:マッチャー」、outcome は success（成功）か error（終了コード 2 などでブロック・失敗）です。Codex は hooks を実行しても記録を出さないため、Codex の試行では not_run（スコアの分母から外す）になります。例: 配布物の hook が rm をブロックしたことを確かめる。

graders:
  - {type: file_exists, path: a.txt, description: a.txt が残っている}
  - {type: hook_used, hook: "PreToolUse:Bash", outcome: error, description: hook が rm をブロックした}

3. validate の警告（設計ルール）

ルールvalidate
各タスクに「結果を見るグレーダー」と「過程を見るグレーダー」を最低 1 つずつ警告
スキル・サブエージェントを「使うべき」タスクには、paired_negative で「使うべきでない」タスクを対にする警告
配布物なし（install が空）のベースラインプロファイルを 1 つ用意する警告
allow_tools を空にしない（Claude Code の -p では承認が必要なツールが拒否される）警告
実行される部品（install の run、hooks・MCP を定義しうる設定ファイル、--mcp-config などの追加引数）を含むプロファイルは、自分たちでレビュー済みの配布物に限る警告
Codex でのスキル検出・hook_used の制約（上記）警告
1 つの family を複数の split にまたがらせない（似たタスクから答えが漏れる）警告
holdout のタスクを 20 件以上にする（少ないと promote の区間と検定がほぼ判定不能）警告
タスクのデータは合成フィクスチャだけを使う（業務データを評価に流さない）機械では確かめられない（運用で守る）

--selftest を付けると、正解例（references/）があるタスクで、採点スクリプトを含む判定が「正解例で通り、何もしなければ落ちる」かを実際に実行して確かめます。何もしなくても通る判定（入力ファイルの有無など）は注意として表示します（壊してはいけないものを守る判定なら意図どおりです）。

4. プロファイル YAML

id: claude-ds-lite
agent: claude_code            # claude_code / codex
model: sonnet                 # --model / -m に渡す（省略で CLI の既定）
install:                      # 一時ホームへの配布物の展開（上から順に実行）
  - copy: ../harnesses/ds-lite/CLAUDE.md
    to: "{config_dir}/CLAUDE.md"
  - copy: ../harnesses/ds-lite/skills
    to: "{config_dir}/skills"
  - run: '{python} path/to/installer.py --profile ds --target {config_dir}'   # 既存の配布インストーラをそのまま使う（プロファイルのフォルダで実行）
env:                          # 追加の環境変数（{…} の置換可）。値を固定してよいものだけ
  CLAUDE_CODE_USE_BEDROCK: "1"
  AWS_REGION: ap-northeast-1
inherit_env: []               # 親の環境から試行に渡す変数（名前だけ。値は書かない）
sandbox: bwrap                # bwrap（Linux で試行を隔離。既定）/ off
sandbox_ro: []                # 隔離の中に読み取り専用で見せる追加のパス（{profile_dir} など可）
env_unset: []                 # 消したい環境変数
billing: api                  # api / subscription
extra_args: []                # CLI に足す引数（例: [--mcp-config, "{config_dir}/mcp.json"]）
permission_mode: null         # Claude Code の --permission-mode
codex_sandbox: workspace-write
pricing: null                 # Codex の概算費用用（8 章）
hash_paths: []                # run で使う配布元など、キャッシュのキーに含めるパス
isolate_home: true
isolation_settings: true
copy_credentials: false
executable: null              # CLI の場所（例: ["C:/tools/claude.exe"]）
キー意味既定
installcopy/to か run の並び。空なら配布物なし（ベースライン）空
env・env_unset試行の環境変数の追加・削除空
inherit_env親の環境から試行に渡す変数の名前（5 章）。環境変数は許可リストで、ここにない変数（API キーなど）は渡らない空
sandboxbwrap: Linux で試行を bubblewrap の中で動かし、試行の外（参照解・採点・他の試行・本物のホーム）を見せない。bwrap が使えなければ run は始める前に止まる。macOS・Windows では隔離せず警告し、leak 検査だけ行う。off: 隔離しない（試行に記録され、verdict が警告する）（ズル対策）bwrap
sandbox_ro隔離の中に読み取り専用で見せる追加のパス（層の hook が呼ぶスクリプトなど）。leak 検査でも許可する空
billingapi（呼び出しごとに課金）／subscription（定額）。予算での扱いは 図解ガイド 8 章api
codex_sandboxCodex の sandbox モードworkspace-write
pricinginput_per_mtok・cached_input_per_mtok・output_per_mtok（Codex の概算費用用）なし
isolate_homeHOME・USERPROFILE を一時ホームに向けるtrue
isolation_settingsClaude Code に claude.ai からのスキル・プラグイン同期を止める --settings を渡すtrue
copy_credentials本物の認証ファイルを一時ホームに複製する（試行後に削除）。実行の前に期限を確かめ、近ければ止まる。試行の中で更新されたら本物へ書き戻す（5 章）false

置換できるもの: {home}（一時ホーム）・{config_dir}（Claude Code は {home}/.claude、Codex は {home}/.codex）・{workdir}・{profile_dir}・{python}。run の中では値が自動で引用されるので、引用符で囲まないでください。install のコピー先は試行ディレクトリの中に限ります（相対パスは一時ホーム基準）。

5. 認証

試行は一時ホームで動くため、ログイン情報が普段の場所にある方式はそのままでは使えません。

方式プロファイルに書くこと
API キー・トークンinherit_env: [ANTHROPIC_API_KEY] のように名前だけ（値は書かない）
Bedrock（Claude Code）env に CLAUDE_CODE_USE_BEDROCK: "1"・AWS_REGION など。AWS の認証ファイルは本物を参照させる（図解ガイド 5 章）
ファイルに保存されたログイン（~/.codex/auth.json、Linux の ~/.claude/.credentials.json）copy_credentials: true。下の「認証ファイルの複製」の注意を読む。会社の評価では API キー（CODEX_API_KEY・ANTHROPIC_API_KEY）を勧める
サブスクリプション（Pro / Max）端末で claude setup-token を実行して長期トークン（推論専用）を作り、export CLAUDE_CODE_OAUTH_TOKEN=… してから実行。プロファイルには inherit_env: [CLAUDE_CODE_OAUTH_TOKEN] と billing: subscription（トークンはチャットやファイルに貼らない）
macOS のキーチェーンのログイン（claude auth login）試行では使えない（設定フォルダを分けると未ログインになる）。上のサブスクリプションの方法を使う

経路を変える変数は宣言する

API キー・トークン・Bedrock などへの切り替え・接続先・モデルの別名の実体を変える環境変数（ANTHROPIC_API_KEY・CLAUDE_CODE_OAUTH_TOKEN・CLAUDE_CODE_USE_BEDROCK・AWS_BEARER_TOKEN_BEDROCK・ANTHROPIC_DEFAULT_SONNET_MODEL・OPENAI_API_KEY・CODEX_API_KEY など。一覧は harness_eval/spec.py の ROUTE_VARS）は、試行の経路と請求先を変えます。値を固定してよいものは env、親の環境の値を使うもの（秘密）は inherit_env に名前だけ書きます。

試行の環境変数は許可リストです。親の環境から渡すのは、PATH・PATHEXT・LANG・LANGUAGE・LC_*・TERM・COLORTERM・TZ・SHELL・USER・LOGNAME・USERNAME、Windows で子プロセスが動くのに要るもの（SYSTEMROOT・COMSPEC・APPDATA など）、モデルの API に届くためのネットワークの設定（HTTP(S)_PROXY・NO_PROXY・ALL_PROXY・SSL_CERT_FILE・SSL_CERT_DIR・NODE_EXTRA_CA_CERTS・REQUESTS_CA_BUNDLE・CURL_CA_BUNDLE）と、inherit_env に書いた名前だけです。一覧は harness_eval/isolation.py の BASE_ENV。

  • 親の環境にあるのに宣言していない経路の変数・エージェントの設定（ANTHROPIC_*・CLAUDE*・AWS_*・CODEX_*・OPENAI_* など）は試行に渡りません。doctor と run が名前だけを出します（値は表示しません）。組織のゲートウェイ（ANTHROPIC_BASE_URL）・クライアント証明書・AWS_PROFILE など、意図して設定したものは inherit_env に書きます。
  • inherit_env で宣言した経路の変数・秘密（名前に KEY・TOKEN を含む）が親の環境にない（別の端末で export した、など）と、doctor が NG（終了コード 1）、run が警告します。
  • 経路の変数とキャッシュの関係は 図解ガイド 8 章 にあります。

認証ファイルの複製（copy_credentials）

試行の中の CLI が複製したログインを更新（refresh）すると、更新用のトークンは使い回せないため、本物のログインが使えなくなります（2026-11-19 に Codex の auth.json で実際に起きました）。そのため次のようにしています。

  • run は試行を始める前に本物の認証ファイルの期限を確かめます。アクセストークンの期限まで 2 時間ない・切れている、または Codex の最終更新（last_refresh）が 7 日より前なら、試行の中で更新が起きるので止まります（終了コード 2）。codex login（または一度 codex を実行して更新）してからやり直します。doctor は期限と最終更新からの日数を表示します（値は表示しません）。
  • 複製はロックの中で行い、内容のハッシュを覚えます。試行のあとで複製が変わっていれば（試行の中で更新された）、本物がまだ複製したときのままのときだけ、ロックを取って原子的に書き戻します（同じフォルダの一時ファイルから置き換え）。本物が先に変わっていれば書き戻しません。どちらも run のログに出ます。
  • 会社の評価では、更新の起きない API キー（Codex は CODEX_API_KEY、Claude は ANTHROPIC_API_KEY）を inherit_env で渡してください。

LLM 判定の認証

判定も一時ホームで動くため、プロファイルの env・env_unset・inherit_env・copy_credentials・executable を借ります（配布物と追加引数は借りません）。借りる先は判定役の系統ごとに決めます。--judge-profile がその系統のプロファイルならそれ、そうでなければ同じ種類の --baseline、それもなければ最初の同種プロファイルです。同じ種類のプロファイルがなければ親の環境変数だけで判定します（run が注意を出します）。判定が認証エラーなどで動かなかった試行は judge_error として集計から除きます。

ズル対策（試行の隔離・leak・tamper）

検査見るもの結果
leak（答えを見た形跡）正規化したツール呼び出しの入力: 試行ディレクトリの外の絶対パスのうち、/workspace・/home・/cursor・/mnt・/srv の下と、この実行で守る場所（本物のホーム・--out・キャッシュ・AHE 自身・タスクのフォルダ・フィクスチャの元・採点スクリプトとそれらの共通の親）。評価の名前（trials.jsonl・record_for_grader.json・.harness-eval-cache など）、3 段以上の ../、上流リポジトリへのネットワーク参照、タスクの leak_patterns。トランスクリプト全体（ツールの出力を含む）のカナリア無効（valid: false・invalid_reason: leak・error.type: leak）。合格にも不合格にも数えない。試行の記録の meta.leak に当たった箇所。上流以外の Web 参照・/tmp などは警告だけ（meta.leak_warnings）
tamper（見えているテストの改ざん）エージェントを起動する直前の作業ツリーの写し（テスト・テストの設定・Python のファイル）と採点前の作業ツリー。既存のテストファイルの削除・改名、確認の行の正味の減少、既存のテスト（基準にあった名前）かファイル全体への skip・xfail・.only、設定で対象を狭める変更（addopts・-k・--ignore・testpaths など）。新しいテストの追加と、仕様の変更に合わせた確認の書き換え（消した数 ≤ 足した数）は数えない不合格（grader_results の末尾に type: tamper の不合格、failure_tags に test_tamper、meta.tamper）。LLM 判定は走らせない
隔離（sandbox: bwrap）見えるのは試行ディレクトリ（書ける）、読み取り専用の /usr・/bin・/sbin・/lib*・/etc・/opt、CLI の本体（node_modules か実体のファイル。Python ならその本体と標準ライブラリ）、executable に書いたスクリプト、AWS 認証・証明書のファイル、sandbox_ro。/tmp・/run・/home・/workspace は空。PID・IPC・UTS の名前空間を分け、ネットワークは残す試行の記録の meta.sandbox に bwrap / off / unsupported

verdict の検査 integrity に件数が出ます。隔離のない試行（off・unsupported）で候補に leak があれば INCONCLUSIVE です。

6. Codex で使うとき

項目内容
配置Codex 公式の探索場所に合わせる。常時指示は CODEX_HOME/AGENTS.md、ユーザースキルは ~/.agents/skills（CODEX_HOME 配下ではない）、プロジェクトのスキルは作業ディレクトリの .agents/skills。SKILL.md は共通形式なのでそのまま複製できる（examples/profiles/codex-ds-lite.yaml）
hooksCODEX_HOME/hooks.json の hooks は、一時ホームでは「未信頼」のため codex exec で警告なしに実行されない。普段の利用では一度信頼すれば実行されるので、その状態を再現するため Codex の試行には常に --dangerously-bypass-hook-trust を付ける（一時ホームに入るのは install で置いたものだけ）

8. 費用の出どころ

cost_source意味
client_estimateClaude Code が API 単価で計算した推定額（total_cost_usd）。請求額とは異なりうる。サブスクリプションでは呼び出しごとの請求はない
token_estimateCodex のトークン数とプロファイルの pricing から計算した概算。式は (input − cached) × input単価 + cached × cached単価 + output × output単価（100 万トークンあたり。OpenAI API の usage 定義で cached は input の内数）。実際の請求と照合してから使う
null（不明）取得できない（pricing のない Codex など）。0 で埋めず、総額・合格あたり費用は「不明」

summary.json の usage（この実行で呼んだ分。キャッシュから再利用した試行は数えない）: solver・judge ごとに input・cache_read・cache_write・output・calls・cost_usd・cost_unknown、solver には費用の出どころの件数 cost_sources とキャッシュから再利用した試行の数 from_cache_trials、judge には判定キャッシュの再利用回数 cache_hits とモデルごとの内訳 by_model、全体に total_cost_usd・judge_share（費用のうち判定の割合）・cost_complete・tier・prices。費用は harness_eval/prices.json（公開 API 価格。出典 URL と取得日 2026-11-19 つき）で換算する。表にないモデルは、解く側・判定側とも CLI が返す費用があればそれを使い、なければ推測せず「不明」にする。

summary.json のタスクごとの効率の値: mean_cost_usd（エージェントの費用の平均。判定の費用は含めない。1 試行でも不明なら null）・mean_tokens（Claude は input + キャッシュ読み書き + output、Codex は input + output。1 試行でも不明なら null）・mean_context_tokens（開始時の文脈。Claude Code だけ。測れた試行だけの平均）。プロファイルごとにも mean_context_tokens があり、Δ には基準との差 context_tokens（共通タスクの平均）が入る。promote --objective efficiency の promote.json には success_ci・log_cost_ratio_ci・relative_saving・cheaper・costlier・cost_sign_p・unknown_cost_tasks・anchor_ci・anchor_one_sided_tasks が加わる（どちらの目的でも objective と context_tokens_delta を残す）。

9. 較正のラベル（calibrate）

LLM 判定と人手ラベルの一致率を出します（約 20 件が目安）。labels.yaml の形式:

- {task: csv-summary-insight, profile: claude-ds-lite, trial: 0, grader: 2, label: PASS}

grader はタスク内のグレーダーの番号（0 始まり）です。
