1. タスク YAML

id: csv-summary-format              # 英数字・_ . -
description: 月別集計で配布ルールの出力形式が守られるか
targets: [claude_code, codex]       # 実行するエージェント（既定は両方）
tags: [instructions, smoke]         # --tag で絞り込む
fixture: ../fixtures/sales_synthetic   # 試行ごとに作業ディレクトリへ複製（ファイル 1 つでも可）
prompt: |
  sales.csv を月別に集計して summary.md にまとめてください。
limits: {max_turns: 15, timeout_s: 300, max_budget_usd: 0.5}
allow_tools: [Read, Write, Edit, Bash, Skill]
deny_tools: []
paired_negative: arithmetic-no-skill            # 対になる「してはいけない」タスク（任意）
split: dev                          # 自己改善ループ用の分割 train / dev / holdout（任意）
family: monthly-report              # 似たタスクのグループ（任意。既定はタスク id）
graders:
  - type: command
    run: '{python} {task_dir}/../checks/check_monthly_totals.py {task_dir}/../fixtures/sales_synthetic/sales.csv'
    weight: 2
  - type: file_contains
    path: summary.md
    pattern: '^\|\s*月\s*\|\s*売上合計\s*\|'
    category: instruction_violation
  - type: tool_used
    tool: Bash|shell
    input_match: 'rm\s+-rf'
    max: 0

相対パスはタスクファイルの場所が基準です。未知のキーはエラーになります。

キー意味既定
id・prompt必須。プロンプトは CLI に標準入力で渡す—
targetsclaude_code・codex両方
fixture入力データ（合成データだけ）なし
limits.max_turns・limits.max_budget_usd1 試行のターン数・費用の上限（Claude Code のみ）20・なし
limits.timeout_s1 試行の時間の上限。超えたら子孫プロセスごと止める600
allow_tools・deny_toolsClaude Code の --allowedTools・--disallowedTools。-p では承認が必要なツール（Write・Edit・Bash など）は許可しないと拒否される空
paired_negativeスキル・サブエージェントを「使うべきでない」対のタスク idなし
description・tags説明と絞り込み用のタグ空
split自己改善ループでの使い道（train・dev・holdout。図解ガイド 11 章）。run --split で絞り込むなし（分割なし）
family似たタスクのグループ（英数字・_ . -）。分割はグループ単位にするタスク id

2. グレーダー

type見るもの主なキー種別
file_exists作業ディレクトリのファイルの有無path結果
file_containsファイル内容の正規表現（複数行モード）path, pattern結果
regex最終応答の正規表現pattern結果
command独自スクリプト。終了コード 0 で合格run, timeout_s結果
llmLLM 判定（PASS / FAIL / UNKNOWN）criteria, focus（final かファイルパス）, max_chars結果
tool_usedツール呼び出しの回数tool（名前の正規表現・完全一致）, input_match, min, max, include_subagents過程
skill_usedスキル呼び出しの回数skill, min, max過程
subagent_usedサブエージェント呼び出しの回数name, min, max過程
hook_usedhook の実行回数（Claude Code のみ）hook（イベント:マッチャー の正規表現・完全一致）, outcome, min, max過程
  • 全グレーダー共通: weight（既定 1）・negate（判定を反転）・category（失敗分類のタグ。既定は種類ごとに wrong_output・process_violation・skill_selection・delegation・hook）・description。
  • min・max を省くと「1 回以上」、max だけ書くと「0〜max 回」。
  • skill_used・subagent_used・hook_used で 1 回以上を求める判定は「配布物がないと通らない判定」として扱います（図解ガイド 7 章の Δ から両側とも除く。試行の合否とスコアには入る）。

command の書き方

  • run では {python}（実行中の Python）・{workdir}・{task_dir} を使えます。作業ディレクトリで実行され、環境変数 TRIAL_WORKDIR と TRIAL_RECORD（試行レコード JSON のパス）が渡ります。
  • 置換した値はシェル用に自動で引用されるので、YAML 側で "{task_dir}" のように囲まないでください（空白を含むパスで壊れます）。
  • 正解は元のフィクスチャから計算します。作業ディレクトリのファイルはエージェントが書き換えられるからです（同梱の採点スクリプトは元の sales.csv を引数で受け取ります）。
  • 「形式」と「正しさ」は別の判定に分け、形式の違いで正しさを落とさないようにします（同梱の check_monthly_totals.py は初版でこれを誤り、実出力で見つけて直しました。回帰テストは tests/data/summaries）。

ツール名はエージェントで違う

エージェントツール名
Claude CodeBash・Write・Edit・Skill・Agent など
Codexshell（コマンド実行）・file_change・web_search・collab:<操作>
共通（MCP）mcp__<サーバー>__<ツール>

両方で同じタスクを使うなら tool: Bash|shell のように両方を書きます。Codex のスキル検出は推定（SKILL.md を読むシェルコマンドから名前を拾う）なので、Codex では成果物を見るグレーダーを主にしてください。

hook_used

Claude Code の --include-hook-events の記録を数えます（このフラグは hook_used を使うタスクにだけ付けます）。hook は PreToolUse:Bash・SessionStart:startup のような「イベント:マッチャー」、outcome は success（成功）か error（終了コード 2 などでブロック・失敗）です。Codex は hooks を実行しても記録を出さないため、Codex の試行では not_run（スコアの分母から外す）になります。例: 配布物の hook が rm をブロックしたことを確かめる。

graders:
  - {type: file_exists, path: a.txt, description: a.txt が残っている}
  - {type: hook_used, hook: "PreToolUse:Bash", outcome: error, description: hook が rm をブロックした}

3. validate の警告（設計ルール）

ルールvalidate
各タスクに「結果を見るグレーダー」と「過程を見るグレーダー」を最低 1 つずつ警告
スキル・サブエージェントを「使うべき」タスクには、paired_negative で「使うべきでない」タスクを対にする警告
配布物なし（install が空）のベースラインプロファイルを 1 つ用意する警告
allow_tools を空にしない（Claude Code の -p では承認が必要なツールが拒否される）警告
実行される部品（install の run、hooks・MCP を定義しうる設定ファイル、--mcp-config などの追加引数）を含むプロファイルは、社内でレビュー済みの配布物に限る警告
Codex でのスキル検出・hook_used の制約（上記）警告
1 つの family を複数の split にまたがらせない（似たタスクから答えが漏れる）警告
holdout のタスクを 20 件以上にする（少ないと promote の区間と検定がほぼ判定不能）警告
タスクのデータは合成フィクスチャだけを使う（社内データを評価に流さない）機械では確かめられない（運用で守る）

--selftest を付けると、正解例（references/）があるタスクで、採点スクリプトを含む判定が「正解例で通り、何もしなければ落ちる」かを実際に実行して確かめます。何もしなくても通る判定（入力ファイルの有無など）は注意として表示します（壊してはいけないものを守る判定なら意図どおりです）。

4. プロファイル YAML

id: claude-ds-lite
agent: claude_code            # claude_code / codex
model: sonnet                 # --model / -m に渡す（省略で CLI の既定）
install:                      # 一時ホームへの配布物の展開（上から順に実行）
  - copy: ../harnesses/ds-lite/CLAUDE.md
    to: "{config_dir}/CLAUDE.md"
  - copy: ../harnesses/ds-lite/skills
    to: "{config_dir}/skills"
  - run: '{python} path/to/installer.py --profile ds --target {config_dir}'   # 社内インストーラをそのまま使う（プロファイルのフォルダで実行）
env:                          # 追加の環境変数（{…} の置換可）。値を固定してよいものだけ
  CLAUDE_CODE_USE_BEDROCK: "1"
  AWS_REGION: ap-northeast-1
inherit_env: []               # 親の環境の値を使う経路の変数（名前だけ。値は書かない）
env_unset: []                 # 消したい環境変数
billing: api                  # api / subscription
extra_args: []                # CLI に足す引数（例: [--mcp-config, "{config_dir}/mcp.json"]）
permission_mode: null         # Claude Code の --permission-mode
codex_sandbox: workspace-write
pricing: null                 # Codex の概算費用用（8 章）
hash_paths: []                # run で使う配布元など、キャッシュのキーに含めるパス
isolate_home: true
isolation_settings: true
copy_credentials: false
executable: null              # CLI の場所（例: ["C:/tools/claude.exe"]）
キー意味既定
installcopy/to か run の並び。空なら配布物なし（ベースライン）空
env・env_unset試行の環境変数の追加・削除空
inherit_env親の環境の値を使う経路の変数の名前（5 章）空
billingapi（呼び出しごとに課金）／subscription（定額）。予算での扱いは 図解ガイド 8 章api
codex_sandboxCodex の sandbox モードworkspace-write
pricinginput_per_mtok・cached_input_per_mtok・output_per_mtok（Codex の概算費用用）なし
isolate_homeHOME・USERPROFILE を一時ホームに向けるtrue
isolation_settingsClaude Code に claude.ai からのスキル・プラグイン同期を止める --settings を渡すtrue
copy_credentials本物の認証ファイルを一時ホームに複製する（試行後に削除）false

置換できるもの: {home}（一時ホーム）・{config_dir}（Claude Code は {home}/.claude、Codex は {home}/.codex）・{workdir}・{profile_dir}・{python}。run の中では値が自動で引用されるので、引用符で囲まないでください。install のコピー先は試行ディレクトリの中に限ります（相対パスは一時ホーム基準）。

5. 認証

試行は一時ホームで動くため、ログイン情報が普段の場所にある方式はそのままでは使えません。

方式プロファイルに書くこと
API キー・トークンinherit_env: [ANTHROPIC_API_KEY] のように名前だけ（値は書かない）
Bedrock（Claude Code）env に CLAUDE_CODE_USE_BEDROCK: "1"・AWS_REGION など。AWS の認証ファイルは本物を参照させる（図解ガイド 5 章）
ファイルに保存されたログイン（~/.codex/auth.json、Linux の ~/.claude/.credentials.json）copy_credentials: true
サブスクリプション（Pro / Max）端末で claude setup-token を実行して長期トークン（推論専用）を作り、export CLAUDE_CODE_OAUTH_TOKEN=… してから実行。プロファイルには inherit_env: [CLAUDE_CODE_OAUTH_TOKEN] と billing: subscription（トークンはチャットやファイルに貼らない）
macOS のキーチェーンのログイン（claude auth login）試行では使えない（設定フォルダを分けると未ログインになる）。上のサブスクリプションの方法を使う

経路を変える変数は宣言する

API キー・トークン・Bedrock などへの切り替え・接続先・モデルの別名の実体を変える環境変数（ANTHROPIC_API_KEY・CLAUDE_CODE_OAUTH_TOKEN・CLAUDE_CODE_USE_BEDROCK・AWS_BEARER_TOKEN_BEDROCK・ANTHROPIC_DEFAULT_SONNET_MODEL・OPENAI_API_KEY・CODEX_API_KEY など。一覧は harness_eval/spec.py の ROUTE_VARS）は、試行の経路と請求先を変えます。値を固定してよいものは env、親の環境の値を使うもの（秘密）は inherit_env に名前だけ書きます。

  • 宣言せずに親から引き継いでいる変数と、inherit_env で宣言したのに設定されていない変数（別の端末で export した、など）があると、doctor が NG（終了コード 1）、run が警告します。
  • 経路の変数とキャッシュの関係は 図解ガイド 8 章 にあります。

LLM 判定の認証

判定も一時ホームで動くため、プロファイルの env・env_unset・copy_credentials・executable を借ります（配布物と追加引数は借りません）。借りる先は --judge-profile、省略時は判定エージェントと同じ種類の --baseline、それもなければ最初の同種プロファイルです。判定が認証エラーなどで動かなかった試行は judge_error として集計から除きます。

6. Codex で使うとき

項目内容
配置Codex 公式の探索場所に合わせる。常時指示は CODEX_HOME/AGENTS.md、ユーザースキルは ~/.agents/skills（CODEX_HOME 配下ではない）、プロジェクトのスキルは作業ディレクトリの .agents/skills。SKILL.md は共通形式なのでそのまま複製できる（examples/profiles/codex-ds-lite.yaml）
hooksCODEX_HOME/hooks.json の hooks は、一時ホームでは「未信頼」のため codex exec で警告なしに実行されない。普段の利用では一度信頼すれば実行されるので、その状態を再現するため Codex の試行には常に --dangerously-bypass-hook-trust を付ける（一時ホームに入るのは install で置いたものだけ）
効かない項目タスクの max_turns・max_budget_usd・allow_tools・deny_tools とプロファイルの permission_mode（対応するフラグがない）。Codex の試行は timeout_s と codex_sandbox で制限する。ターン数を出さないので、レポートの平均ターンは空欄
ないものClaude Code のサブエージェント定義を Codex 形式（.codex/agents/*.toml）に変換する機能

8. 費用の出どころ

cost_source意味
client_estimateClaude Code が API 単価で計算した推定額（total_cost_usd）。請求額とは異なりうる。サブスクリプションでは呼び出しごとの請求はない
token_estimateCodex のトークン数とプロファイルの pricing から計算した概算。式は (input − cached) × input単価 + cached × cached単価 + output × output単価（100 万トークンあたり。OpenAI API の usage 定義で cached は input の内数）。社内の請求と照合してから使う
null（不明）取得できない（pricing のない Codex など）。0 で埋めず、総額・合格あたり費用は「不明」

9. 較正のラベル（calibrate）

LLM 判定と人手ラベルの一致率を出します（約 20 件が目安）。labels.yaml の形式:

- {task: csv-summary-insight, profile: claude-ds-lite, trial: 0, grader: 2, label: PASS}

grader はタスク内のグレーダーの番号（0 始まり）です。
