Architecture decision

ゼロから作らない。フォークもしない。

BenchFlow 0.6.7 とnative Claude adapterを、同じ統制レイヤーの下で使う

BenchFlowには、Claude Code / Codexの実行、複数sandbox、認証adapter、skills比較、複数trial、軌跡・telemetry保存、決定的verifier、paired bootstrap、GEPA向けexportが既にある。実行基盤を再実装する価値はない。Phase 0ではinstalled wheelとCLIを0.6.7へ固定し、このMacのClaude Pro認証経路をredacted doctorで確認した。実taskへのlive応答はPhase 1 pilotまで行わない。

ローカルPro認証はmacOS Keychainにあり、sandboxへ安全に移せないため、信頼済みの静的instruction / skillだけnative claude -pで実行する。社内BedrockはBenchFlow + AWS AgentCore/CodeBuildをDocker不要の候補にする。実験統制はどちらも同じPython control planeが持つ。

Decision CONDITIONAL ADOPT + EXTEND

benchflow==0.6.7
Apache-2.0 / Python 3.12+

内部APIには依存せず、CLIとpinned producer artifactsを既定の境界にする。必要時だけ狭いpre-launch pluginを使い、0.xの変更をcontract testで検知する。

採用前の技術gate: 公開CLI・公開API・plugin契約だけで、home-scoped Hooks / MCP / settings / agents / skillsをvariantごとに完全隔離できるかを短いspikeで証明する。実ユーザーhomeを変更しない、A/B間で状態が漏れない、credentialがchild toolから読めない、egress policyが実測で強制されることが合格条件。0.6.7の期待機能もinstalled wheelでcontract testする。subprocess/artifact境界を優先し、足りないpre-launch overlayだけ狭いpluginまたはupstream hookで補う。それも不可能な場合だけforkを再検討する。

Evaluation protocol

「良さそう」を出荷根拠にしない

1. Taskを先に検証

  • 実際の失敗・反復作業からtask familyを作る
  • 期待成果と禁止行動を観測可能にする
  • reference solutionが通り、known-badが落ちることを確認
  • 開発用とprivate temporal holdoutを分離する

2. 同一taskを対で実行

  • baselineとcandidateを同じmodel・budget・環境で比較
  • AB / BAを無作為にcounterbalance
  • 時間差を減らすため同一pairを隣接実行
  • 各trialはclean sandboxから開始

3. 出荷gateは複数軸

  • 品質の非劣性または優越性
  • 成功1件あたりの資源削減
  • 安全・policy違反ゼロ
  • placeboと既知不良controlを識別

測定単位

Pass@1初回で実用成果に到達した率。主要品質指標。
Passkk回すべて成功する信頼性。ばらつきを隠さない。
Costattempt当たりと成功当たりの両方。telemetry不明はゼロにしない。
Safety違反を0/Nとpolicy class coverage、上側信頼限界で示す。

Judgeの優先順位

  1. test、schema、diff、artifact検査など決定的grader
  2. 真に必要なpolicyだけtrace検査
  3. 主観品質のみ、blind化したLLMまたは人間評価

LLM judgeは順序を無作為化し、variant名を隠し、Unknownを許可する。人間との一致率を先に校正する。

統計

主要推定量は、各task内の全paired trial差を平均し、そのtask平均をtask間で平均した品質差とする。taskをclusterとして全trialを保持したpaired bootstrap / randomization CIを算出する。

Exact McNemarは、事前規則で各taskを1つのpaired binaryへ縮約した実験に限る。複数trialを独立sampleとしてpoolしない。

20–50 taskや3 trialは偵察値であり、出荷の普遍的根拠ではない。 非劣性marginも業務損失から事前に決め、結果を見て変更しない。

単一の総合点を主要判定にしない。 重みを変えるだけで勝者が反転する。品質、安全性、コスト、速度、再現性を別々に表示し、hard gateをすべて満たしたvariantだけを配布候補にする。

Pre-registered promotion contract

結果を見る前に勝ち方を固定する

各experimentはmachine-readableなpromotion contractをmanifestへ埋め込み、content hashで固定する。runnerやreviewerが後から条件を変えられないようにし、判定は promote / reject / inconclusive の3値だけを返す。

必須contract

  • primary endpoint、analysis unit、95% CI方式
  • 業務損失から決めた非劣性margin
  • planned tasks / trials、欠測とmultiplicity規則
  • attempt / success双方のcost basis、削減threshold、telemetry completenessと欠測処理。zero-success時は無限大
  • safety taxonomy、分母、coverage、片側上側信頼限界、severity別gate
  • invalid taxonomy、最大retry、非対称invalid率の上限

判定規則

  • 品質下限CIが非劣性margin以上である
  • 事前指定した品質優越またはcost改善を満たす
  • CRITICAL/HIGH safety eventは1件でもreject
  • known-bad controlが通れば評価器ごとreject
  • 必要sample不足、CI跨ぎ、invalid過多、cost欠測過多はinconclusive
  • 人間はpromoteを承認できるがrejectを上書きできない

Invalid / retry

agent開始前のsandbox障害など、variant非依存と事前定義できる事象だけをinvalid候補にする。timeout、OOM、tool失敗は原則treatment outcome。分類者にはvariant名と品質結果を見せず、全attemptとarm別invalid率を保存する。

retry上限と非対称率thresholdを超えたらpromoteしない。pairを再実行しても元attemptを削除せず、replacementをprimary observationへ差し替えない。primaryは全treatment-attributable failureを含むintent-to-evaluate分析とする。

Sealed holdout

PromotionBrokerだけがtask、test、gold patchを含むprivate temporal holdoutを読める。optimizerとoperatorの通常環境にはread権限を与えず、candidate凍結後にbrokerがmaterializeし、承認済みaggregateだけを返す。

公開taskとのsimilarityを監査し、open-web条件は別stratumにする。releaseごとにcandidateは1つだけで、結果を返した評価はreleaseを消費する。全accessを監査し、holdout trajectoryをGEPA/optimizerへ渡さない。

Portability

path、process、sandboxをProtocol化し、shell文字列ではなくargvで実行する。Macはnative Claude / Apple Container、Windowsはhost control plane + remote AgentCore / CodeBuildから始める。native Windows taskは現時点の対応範囲外。

Cost semantics

provider請求額、Claude client推計USD、token usage、取得不能を区別する。既定は完全なpaired telemetryを必須とし、欠測があればcost gateをinconclusiveにする。例外は、事前指定したcompleteness threshold・candidate側の保守的上限代入・arm間欠測差gateをすべて満たす場合だけ。placeholder zeroを利用ゼロと解釈せず、Codex tokenを架空のUSDへ換算しない。

Raw evidence

BenchFlowが永続化したredacted producer artifactは変更せず保存する。当ツールのversioned projectionはlossyになり得るため、source・producer version・導出式を付ける。失敗trialも捨てない。

Execution profiles

認証・費用・隔離を混ぜない

Local Claude Pro

このMacのClaude.ai Pro OAuthをnative claude -pで使う。Phase 0 doctorはPro種別、固定した実行file、API / gateway / provider override不在を確認し、probeへsecretを継承しない。

範囲: T1の信頼済みMarkdown instruction / skillとsynthetic taskだけ。Phase 1 runnerでproject settings限定、MCP拒否、session非永続、subprocess credential scrubを実装するまで実行範囲を拡大しない。USD使用額は取得不能であり、ゼロやAPI価格へ換算しない。

Corporate Claude Bedrock

CLAUDE_CODE_USE_BEDROCK=1、固定model / inference profile、短命な個人別roleまたはgateway identityを使う。Bedrock invocation logでtokenを追跡し、CUR 2.0で請求額を照合する。

予算: 1人月額$1,500。Phase 0は独立accountのDecimal演算とsource digest付きcost claimだけを実装済み。実行前reserve、永続・原子的な個人別ledger、gateway deny、CUR照合はPhase 1以降の必須gateであり、現時点では支出を強制停止できない。

Corporate Codex

Claudeとは別の月額$1,500 ledgerを持ち、借用・合算しない。ChatGPT subscriptionにはper-run USD台帳がないため、API課金または社内billing sourceが決まるまでfinancial gateはinconclusive。

範囲: Phase 0 profileはexecution_enabled=falseで常に拒否する。Codex phaseまでlive実行を保留し、同じtaskでもClaude結果とは別stratumで報告する。

Docker不要の経路: このMacはmacOS 26.3.1 / arm64でApple Container 1.1+の条件を満たすが未導入。Apple Containerはlocal VM隔離には使える一方、BenchFlow 0.6.7ではno-networkを強制できない。社内の第一候補はAgentCore + CodeBuildで、local container runtimeを不要にする。stock 0.6.7はAgentCoreをPUBLIC固定するため、Hooks/MCPにはVPC mode・private subnet・Bedrock endpoint・最小execution roleを設定するreviewed adapterが必要。
現在のready境界: このMacのlocal-claude-pro + native + T1のみ実機診断済み。Apple Containerは未導入、AgentCoreはAWS identity / network-policy probe未実装、CodexはPhase 0停止中のためreadyにならない。

Security boundary

ハーネス自体を未信頼入力として扱う

隔離

毎trialをephemeral workspaceで実行。hostのClaude/Codex設定、MCP、skillsを暗黙継承しない。

Network

BenchFlow 0.6.7の既定はPUBLICでhost allowlistも強制されない。provisioning、model、task service、verifierのegressを分けるenforcement adapterを実装・実測できるまで、untrusted Hooks/MCPを有効化しない。

Credential

個人のpersistent credentialをuntrusted bundleと同居させない。brokered credential、専用disposable eval account、または認証をsandbox外へ置くproxyのどれかを採用gateで証明する。

必須攻撃test: 悪意あるskill / Hook / MCPがcredential file・環境変数を読み、model endpointまたはpublic egressへ送ろうとしても失敗することを観測する。network enforcementを実装できない場合、MVPは承認済みの非実行instruction / skill比較だけに縮退し、PUBLIC egressの残存riskを明示する。
Trust許可する入力実行境界禁止事項
T0任意bundleの静的inspectionmodel / shellなし実行全般
T1review済みMarkdown instruction / skillnative Pro、Apple Container、またはAgentCorescripts、symlink、Hooks、MCP、plugin、remote include
T2署名・hash固定したapproved executable harnessVPC mode AgentCoreまたは同等のreviewed corporate backendpersonal subscription、PUBLIC egress、reusable credential
T3未reviewのHooks / MCP攻撃fixturesynthetic data + offline/mock model + network block-all社内code、実credential、production data
Phase 0 authorization: 実装はT0/T1だけを許可する。T2/T3は、別trust domainが発行する署名済みprobe artifactの検証器が実装されるまで、自己申告のcapabilityが揃っていても常に拒否する。

Recorded decisions

2026-08-15 確定

1. 認証と月額上限

このMacのlive確認はClaude Pro subscriptionを使う。社内ClaudeはBedrock API。社内上限はClaude CodeとCodexで独立して各1人月額$1,500。

実装規則: subscriptionに架空のper-run USDを付けない。Bedrockは個人別AWS attributionで実額を追跡し、Codexのfinancial sourceは後続phaseで確定する。

2. 初期task

選定は委任されたため、外部service不要のsynthetic Python taskから開始する。

採用: regression repair、bounded CLI feature、safe cross-file refactor。各taskにhidden test、reference patch、known-bad patchを持たせる。

3. Docker非依存

社内ではDockerを必須にしない。Mac localはnative Claude / Apple Container、社内はAgentCore + CodeBuildを第一候補にする。

Windowsはhost control plane + AWS remote sandboxから始める。native Windows taskは別canary通過まで非対応。
